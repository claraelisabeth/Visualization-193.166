Edge Path Bundling

Code Documentation

Clara Pichler and Paul Schmitt
Final Project for the Course 193.166 Visualization at the Technical University of Vienna

Overview

This is the comprehensive code documentation for the Edge Path Bundling project, which implements the cutting-edge edge bundling algorithm described in "Edge-Path Bundling: A Less Ambiguous Edge Bundling Approach" by Wallinger et al. (2022). Our implementation provides a complete Python framework for graph visualization with edge bundling capabilities, featuring interactive exploration tools and multi-dataset support.

Edge path bundling addresses the critical challenge of visual clutter in network visualizations by grouping related edges into smooth, bundled paths while preserving the underlying network structure. Unlike traditional edge bundling approaches that can introduce visual ambiguity, this implementation maintains topological correctness through careful path selection and distortion control.

Algorithm Overview

The core algorithm processes edges in weight-descending order, attempting to route each edge through existing bundled paths while respecting a maximum distortion threshold k. The approach ensures that bundled paths remain meaningful representations of the underlying network topology.

Architecture Components

The project follows a modular architecture with clear separation of concerns across four main packages:

  • Core Algorithm (src/core/) - Implementation of the edge path bundling algorithm with spatial distance calculations
  • Data Loading (src/data_loader/) - Specialized loaders for different network dataset formats
  • Interactive Dashboard (src/dashboard/) - Web-based interface for parameter exploration and real-time visualization
  • Visualization Engine (src/visualization/) - Plotly-based rendering with Bézier curve generation and multi-dimensional support

Supported Datasets

The implementation includes three diverse datasets demonstrating the algorithm's versatility across different domains:

  • Air Traffic Networks - Global airport connections using OpenFlights data with great-circle distance calculations
  • Brain Connectivity - Structural connectivity from the Human Connectome Project with 3D MNI coordinate systems
  • Migration Flows - US county-to-county population migration patterns from Census Bureau data

Usage Examples

This section demonstrates how to use the Edge Path Bundling API programmatically. For running the interactive dashboard, see the main project documentation.

Basic Bundling Pipeline

from src.core.bundling import create_graph, bundle_edges
from src.visualization import create_network_visualization

# 1. Prepare node and edge data
nodes = [
    {'id': 0, 'x': -122.4, 'y': 37.8},  # San Francisco
    {'id': 1, 'x': -118.2, 'y': 34.1},  # Los Angeles
    {'id': 2, 'x': -73.9, 'y': 40.7},   # New York
    # ... more nodes
]
edges = [(0, 1), (0, 2), (1, 2)]  # (source, target) tuples

# 2. Create graph with haversine distance (for geographic data)
graph = create_graph(nodes, edges, distance_type='haversine')

# 3. Run edge path bundling algorithm
result = bundle_edges(graph, k=2.0, d=1.5)

# 4. Access results
print(f"Bundled {result['statistics']['bundled']} of {result['statistics']['total_edges']} edges")
for path in result['bundled_paths']:
    print(f"Edge {path['original_edge']} → Path: {path['path']}, Detour: {path['detour_ratio']:.2f}")

bundling.py - Core Algorithm Implementation

This module contains the heart of our edge path bundling system, implementing Algorithm 1 from Wallinger et al.'s paper with additional optimizations for real-world graph processing. The implementation carefully balances computational efficiency with visual quality, providing robust handling of diverse network topologies and coordinate systems.

Edge Path Bundling Algorithm
  1. Initialization: Create auxiliary graph G' from input graph G with spatial edge weights
  2. Edge Sorting: Sort edges E by weight in descending order (heaviest first)
  3. Path Finding: For each edge (u,v), find shortest path in G' excluding locked edges
  4. Distortion Check: Accept path only if distortion ratio ≤ k threshold
  5. Path Locking: Lock all edges in accepted path to prevent reuse
  6. Iteration: Continue until all edges processed or early termination conditions met

Core Functions

bundle_edges(graph: nx.DiGraph, k: float = 2.0, d: float = 1.0, max_edges: int = 500, early_stop: int = 50) → Dict

Main algorithm orchestrator that implements the complete edge path bundling workflow.

  • Input: NetworkX directed graph with spatial node coordinates
  • Parameters: k (distortion threshold), d (edge weight exponent), max_edges (performance limit), early_stop (consecutive failures before stopping)
  • Returns: Dictionary mapping original edges to bundled path sequences
  • Complexity: O(|E| × (|V| + |E|) log |V|) due to repeated Dijkstra calls
create_graph(nodes: List[Dict], edges: List[Tuple], distance_type: str) → nx.DiGraph

Graph construction utility that builds NetworkX graphs from raw coordinate data.

  • Supports both 2D and 3D coordinate systems
  • Automatically calculates spatial edge weights using specified distance metric
  • Handles missing or invalid coordinate data gracefully
  • Preserves original node metadata for visualization purposes

Distance Calculation Functions

haversine_distance(lat1, lon1, lat2, lon2) → float

Great circle distance calculation for geographic coordinates using the Haversine formula.

distance = 2R × arcsin(√(sin²(Δφ/2) + cos φ₁ × cos φ₂ × sin²(Δλ/2)))
  • Use case: Air traffic networks, migration data, any lat/lon coordinate systems
  • Accuracy: Earth radius constant EARTH_RADIUS_KM = 6371.0 km
  • Range: Handles antipodal points correctly
euclidean_distance(x1, y1, x2, y2, z1=None, z2=None) → float

Euclidean distance in 2D or 3D space with optional z-coordinate support.

  • 2D mode: Standard Euclidean distance for planar networks
  • 3D mode: Full spatial distance for brain connectivity data
  • Fallback: Gracefully handles missing z-coordinates

Pathfinding Implementation

dijkstra_with_skip(graph: nx.DiGraph, source, target) → Optional[List]

Modified Dijkstra's algorithm that respects edge skipping for bundle construction.

  • Excludes edges where the skip attribute is True from path consideration
  • Returns shortest available path or None if no valid path exists
  • Uses a custom weight function that returns infinity for skipped edges
  • Maintains NetworkX compatibility for easy integration

Algorithm Parameters

Parameter Type Range Description Impact
k float 1.0 - 10.0 Distortion threshold (path length / direct distance) Higher values allow more bundling but increase distortion
d float 0.5 - 3.0 Edge weight exponent (weight = length^d) Higher values prioritize longer edges for bundling
Performance Considerations: The algorithm's time complexity is dominated by repeated shortest path calculations. For large graphs (>10,000 edges), future approaches might want to consider implementing hierarchical bundling or edge sampling strategies. Current implementation includes early termination heuristics to maintain interactive performance.
Implementation Note: The algorithm maintains topological correctness by ensuring that bundled paths represent valid routes through the network. This distinguishes it from force-directed bundling approaches that may create visually appealing but topologically meaningless edge groupings.

data_loader - Dataset Loading Modules

Collection of specialized data loading modules that handle different dataset formats and coordinate systems. Each loader creates NetworkX graphs with appropriate distance metrics and spatial attributes for the bundling algorithm.

air_traffic.py

Loads OpenFlights airport and route data, handling CSV parsing for airport coordinates and route connections. Data source: OpenFlights Project

load_air_traffic_data(airports_file: str, routes_file: str, distance: str = 'haversine') → Optional[nx.DiGraph]

Main entry point for loading air traffic network data.

  • airports_file: Path to airports.dat (ID, name, city, country, IATA, lat, lon, ...)
  • routes_file: Path to routes.dat (airline, source_airport_id, dest_airport_id, ...)
  • distance: Distance metric ('haversine' for geographic data)
  • Returns: NetworkX DiGraph with airport nodes (x=longitude, y=latitude) and route edges
Helper Functions
  • load_airports(airports_file: str) → Dict - Parses airport CSV, returns dict keyed by airport_id
  • load_routes(routes_file: str, airports: Dict) → List[Tuple[int, int]] - Parses routes, filters invalid entries

brain_connectivity.py

Processes GraphML files from the Human Connectome Project containing 3D brain region coordinates and structural connections. Data source: Brain Graph Project

load_brain_graphml(graphml_file: str) → Optional[nx.DiGraph]

Loads brain connectivity from GraphML format with 3D coordinate support.

  • graphml_file: Path to GraphML file (e.g., HCP connectome data)
  • Coordinate handling: Supports both standard (x, y, z) and HCP format (dn_position_x, dn_position_y, dn_position_z)
  • Edge weights: Computes Euclidean distance between 3D node positions
  • Returns: NetworkX DiGraph with 3D node positions and distance-weighted edges
HCP Format Conversion: The loader automatically converts Human Connectome Project attribute names (dn_position_x, dn_name, etc.) to standard format (x, y, z, name) for compatibility with the bundling algorithm.

migration.py

Parses US Census Bureau county-to-county migration flow data with automatic coordinate generation. Data source: US Census Bureau

load_outflow_data(outflow_file: str, min_flow_threshold: int = 100, distance: str = 'haversine') → Optional[nx.DiGraph]

Loads migration flows from space-separated outflow format.

  • outflow_file: Path to outflow.txt (space-separated: origin_fips dest_fips volume)
  • min_flow_threshold: Minimum flow volume to include (filters small migrations)
  • distance: Distance metric ('haversine' for geographic data)
  • Returns: NetworkX DiGraph with county nodes (x=longitude, y=latitude) and migration edges
Helper Functions
  • _create_us_county_coordinates(county_fips: set) → Dict - Generates approximate county coordinates based on FIPS state codes with random offsets within state boundaries
Coordinate Approximation: Since exact county centroid data is not bundled, coordinates are approximated using state center positions with small random offsets. This is sufficient for demonstrating the bundling algorithm but may not reflect exact geographic positions.

app.py

Interactive Dash web application that provides a user interface for exploring edge path bundling on different datasets. Features parameter controls, real-time visualization updates, and performance optimizations including caching and progressive loading.

Key Features

  • Parameter Controls - Sliders for bundling factor (k), edge weight factor (d), and smoothing level
  • Dataset Selection - Dropdown for switching between brain, air traffic, and migration datasets
  • Visualization Options - Toggle between highlighted (red) and normal (gray) coloring for bundled edges, plus edge thickness control (thick/normal)
  • Performance Optimization - Caching system for datasets and bundling results
  • Responsive Design - Academic-styled interface with sidebar controls and main visualization area
  • Smart Control Disabling - Visualization controls are grayed out when k=1 (no bundling)

Callback Architecture

Uses Dash callbacks for reactive updates: parameter displays update immediately, dataset changes reset controls, bundling recalculation occurs for algorithm parameters, and fast updates for visualization-only changes. Implements smart caching to avoid redundant computations.

Performance Constants

  • Major airports limited to 50 for demonstration
  • Migration data filtered to top 100 counties
  • Minimum flow threshold of 3,000 for migration data
  • Fixed curve sampling at 80 points for smooth rendering

plotly_renderer.py

Comprehensive visualization module that renders bundled graphs using Plotly with support for 2D geographic maps, 3D brain visualizations, and smooth Bezier curve generation. Automatically detects data types and applies appropriate rendering strategies.

Visualization Types

  • Geographic Maps - Uses Plotly's Scattergeo for air traffic and migration data with automatic US/world map detection
  • 3D Brain Visualization - Interactive 3D plots for brain connectivity data with rotation and zoom controls
  • Standard Network Plots - 2D scatter plots for general network data with optional geographic overlays

Curve Generation

Implements smooth Bezier curve generation using recursive subdivision and De Casteljau's algorithm. Supports configurable smoothing levels (adding control points) and sampling resolution. Works in both 2D and 3D coordinate systems for consistent curve appearance.

Performance Features

  • Automatic edge limiting for dense networks (500 for maps, 1000 for 3D)
  • Color scheme optimization for different visualization contexts (highlight/normal modes)
  • Configurable bundled edge thickness (thick/normal/thin)
  • Hover information with path details and distortion ratios
  • Responsive layout configuration for different screen sizes

The module uses explicit dataset type detection for faster rendering, falling back to automatic detection for backward compatibility. Geographic data detection uses coordinate range validation and spread analysis.

curves.py - Bézier Curve Generation

Dedicated module for smooth curve generation following the paper's approach to path visualization. Implements advanced Bézier curve mathematics with recursive smoothing algorithms to create visually appealing bundled edge representations while maintaining mathematical precision.

Curve Generation Pipeline
  1. Control Point Extraction: Extract spatial coordinates from bundled path nodes
  2. Recursive Smoothing: Apply iterative midpoint insertion for smoother curves
  3. Bézier Interpolation: Generate smooth curves using De Casteljau's algorithm
  4. Adaptive Sampling: Create optimal point density for rendering

Core Functions

generate_control_points(path_nodes, node_positions, smoothing_level=2) → List[np.ndarray]

Control point generator that converts bundled paths into smooth curve control points.

  • Input: Node sequence from bundled path, coordinate mapping
  • Process: Extracts coordinates and applies recursive smoothing
  • Returns: Array of control points suitable for Bézier interpolation
  • Default: Level 2 smoothing as recommended in the paper
apply_recursive_smoothing(points, smoothing_level) → List[np.ndarray]

Recursive smoothing algorithm implementing the paper's approach for curve refinement.

  • Iteratively inserts midpoints between existing control points
  • Each iteration doubles the control point density
  • Maintains curve continuity while increasing smoothness
  • Configurable smoothing levels for different quality requirements
generate_bezier_curve(control_points: List[np.ndarray], num_samples: int = 100) → List[Tuple[float, float]]

Bézier curve sampling that generates points along the curve.

  • Supports arbitrary-degree Bézier curves based on control point count
  • Configurable sampling density for different rendering requirements (paper default: 100)
  • Returns list of (x, y) coordinate tuples for easy plotting
  • Optimized for real-time interactive applications

Mathematical Foundation

Bézier Curve Formula: For control points P₀, P₁, ..., Pₙ

B(t) = Σᵢ₌₀ⁿ (n choose i) × (1-t)ⁿ⁻ⁱ × tⁱ × Pᵢ

Where t ∈ [0,1] parameterizes the curve from start to end.

evaluate_bezier_curve(control_points: List[np.ndarray], t: float) → np.ndarray

Single point evaluation on Bézier curve using De Casteljau's algorithm.

  • Numerically stable recursive evaluation
  • Handles edge cases (t=0, t=1) correctly
  • Linear time complexity O(n) for n control points
  • Used internally by generate_bezier_curve for curve sampling

Convenience Function

create_smooth_bundled_path(path_nodes: List, node_positions: dict, smoothing_level: int = 2, num_samples: int = 100) → List[Tuple[float, float]]

Complete pipeline function that combines control point generation, smoothing, and curve sampling.

  • Extracts coordinates from path nodes using the position dictionary
  • Applies recursive smoothing to create control points
  • Generates smooth Bézier curve with configurable sampling
  • Primary function used by plotly_renderer.py for 2D visualizations
3D Curve Support: 3D Bézier curve generation for brain connectivity data is handled internally by plotly_renderer.py using the same recursive smoothing and De Casteljau algorithm, extended to 3D coordinates.
Performance Optimization: Curve generation is cached based on path sequences and smoothing parameters. For interactive applications, consider pre-computing common curve configurations to minimize real-time computational overhead.
Curve Quality vs. Performance: Higher smoothing levels and sample counts improve visual quality but increase computational cost. Recommended settings: smoothing_level=2, num_samples=80 for good balance of quality and performance.
